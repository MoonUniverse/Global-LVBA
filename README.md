# Global-LVBA
## Global LiDAR-Visual Bundle Adjustment

**Global-LVBA** is a globally consistent **LiDAR–Visual Bundle Adjustment** system for **refinement** after LiDAR-inertial-visual odometry (e.g., FAST-LIVO2).  
If you want to push accuracy to the next level, Global-LVBA further optimizes:
- point-cloud map consistency (reducing layering/stratification artifacts).
- camera poses towards **pixel-level reprojection accuracy**.

## 1. Prerequisites
- ROS 2 Humble or newer
- Python 3
- Ceres Solver 2.1.0
- Eigen 3.3.7
- OpenCV 4.2.0
- PCL
- SQLite3
- CURL

## 2. Build

```bash
cd ~/ros2_ws/src
git clone <your-repo-url> Global-LVBA
cd Global-LVBA
git submodule update --init --recursive

cd src/SiftGPU
mkdir -p build
cd build
cmake ..
make -j$(nproc)

cd ~/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select global_lvba
source install/setup.bash
```

If you build this repository in place instead of a larger ROS 2 workspace, the following also works:

```bash
cd /path/to/Global-LVBA
source /opt/ros/humble/setup.bash
colcon build --base-paths .
source install/setup.bash
```

## 4. Configuration

The runtime configuration lives in [config/config.yaml](config/config.yaml).

Important behavior in the ROS 2 version:
- Editing [config/config.yaml](config/config.yaml) does not require rebuilding or reinstalling the package. Restarting the launch command is enough.
- By default, [launch/lvba.launch.py](launch/lvba.launch.py) prefers the source-tree config and RViz files when you run from this repository.
- `data_config.data_path` supports both absolute and relative paths.
- If `data_path` is relative, it is resolved relative to the package root. For example, `dataset/CBD_Building_01/` means `Global-LVBA/dataset/CBD_Building_01/`.
- `data_config.colmap_db_path` is resolved relative to `data_path` when it is not absolute.

Example:

```yaml
data_config:
  data_path: dataset/CBD_Building_01/
  colmap_db_path: Colmap/colmap_sub5.db
```

This resolves to:
- dataset directory: `Global-LVBA/dataset/CBD_Building_01/`
- COLMAP database: `Global-LVBA/dataset/CBD_Building_01/Colmap/colmap_sub5.db`

## 5. Dataset download

The **LVBA-Dataset** ([Google Drive](https://drive.google.com/drive/folders/19fYG4z666hcxyP6StVXs-ZOI2cbHsU5J?usp=drive_link)) is generated from the raw rosbag in **FAST-LIVO2-Dataset** ([Google Drive](https://drive.google.com/drive/folders/1bf5LQ8iSxw-fD8BObZmouw7lRxNacfrA?usp=drive_link)).

💡 **Note:** To prepare your own data with FAST-LIVO2, set `pcd_save_en: false`, `type: 1`, and `img_save_en: true` in the FAST-LIVO2 config to directly generate the required files for Global-LVBA.

## 6. Run
Download the example data from LVBA-Dataset.

Run LVBA only:

```bash
ros2 launch global_lvba lvba.launch.py
```

Run LVBA with RViz2:

```bash
ros2 launch global_lvba lvba.launch.py rviz:=true
```

Run with an explicit config file:

```bash
ros2 launch global_lvba lvba.launch.py config_file:=/absolute/path/to/config.yaml
```

💡 **Note:** We recommend using the `.db` file generated by **COLMAP** to obtain feature correspondences. The built-in SiftGPU extraction/matching in this repo is provided for convenience, but its matching quality is generally inferior to COLMAP.

## 7. Notes

- The default launch behavior does not start RViz2. Pass `rviz:=true` only when you want the visualization UI.
- The provided [rviz_cfg/lv_ba.rviz](rviz_cfg/lv_ba.rviz) is already converted for RViz2 plugin names.
- A recent validation run on ROS 2 completed successfully with exit code `0`, including Ceres optimization convergence and reprojection output generation.
